# Library Audit — June 2026

**Scope:** full doc/code consistency sweep + code audit of `soundcloud-widget-react`, following the June 2026 audits of its siblings (`soundcloud-api-ts`, see its `docs/audit-2026-06.md`), which found docs describing behavior the code did not have. This audit assumed the same failure classes until proven otherwise.
**Method:** every behavioral claim in README.md, llms.txt, llms-full.txt, CHANGELOG.md, and JSDoc was verified against `src/`. Code was treated as the source of truth throughout. The widget-API surface was cross-checked against SoundCloud's official HTML5 Widget docs (developers.soundcloud.com/docs/api/html5-widget). Anything not verifiable from code alone (live widget behavior) is marked **ASSUMED**.
**Result:** audited at v2.0.4, fixed and bumped to v2.1.0. All fixes are non-breaking. Suite: 34 tests passing (there were **zero** tests before this audit); build (tsup) and typecheck green on Node 24 / pnpm 10.23.0. CI history on GitHub was green (unlike the siblings) — but only because the sole workflow was the publish job; there was no test CI at all.

---

## Executive summary

The sibling disease — docs describing behavior the code doesn't have — was present here too, plus one issue the siblings didn't have: **a real npm automation token committed to the public repo's git history** (revoked, but see C1).

The flagship doc claim "URL/param changes trigger `widget.load()` — no iframe remount, no flicker" (llms.txt, README, CHANGELOG 1.0.1) was **false**: the iframe `src` was recomputed on every render, so any `url`/param change navigated the iframe to a fresh player *and* called `widget.load()` — the track loaded twice. The claimed React `>=17` support was also false (`useId` is 18-only; React 17 crashed at render). Every callback-style getter fired its callback twice. The volume API was documented as 0–1 when SoundCloud's official docs say 0–100 — this repo's own demo correctly used 0–100 while the README example `setVolume(0.5)` would produce near-silence. The llms files carried a stale `Version: 2.0.0` header at v2.0.4 — the exact drift vector from the original sibling incident — and CHANGELOG was missing the last four releases. README claimed "tested duplicate-script injection prevention" when the repo had no tests of any kind.

What was verified **correct**: the event/method surface exactly matches SoundCloud's documented Widget API (all 11 events, all methods, honest `SCAudioEventPayload` fields); the script loader is genuinely idempotent and SSR-guarded; rendering touches no browser globals (verified by a bare-Node test); the stable-callback-ref pattern works (no re-bind churn, no stale closures); StrictMode mount/cleanup is symmetric; the 2.0.1 snake_case `load()` fix and the 1.0.8 single-encoding fix are intact (both now pinned by tests); and the cross-references to `soundcloud-api-ts-next` (`getTrack`/`useTrack` signatures) are accurate against the live sibling sources.

## Findings

### Critical

**C1 — Live npm automation token committed to the public repo.**
Evidence: commit `d3e4c2d` (2026-02-28) added `.npmrc` containing a real granular token (`npm_RKzK…Krl`). Commit `8e97709` ("remove npm token from .npmrc") replaced it with an `${NPM_TOKEN}` placeholder — but the token remains fully visible in `git log -p` on GitHub, and in the trees of tags v2.0.1–v2.0.3. The v2.0.1–2.0.3 publish runs also executed `npm publish` with that tracked `.npmrc` present, i.e. likely authenticated with the leaked token rather than OIDC.
**Status:** the token was checked read-only against `registry.npmjs.org/-/whoami` during this audit and returns **401 — already revoked/expired**. No action taken on history: scrubbing requires a force-push rewrite of `main` plus re-tagging (destructive; needs maintainer sign-off), and with the token dead the practical risk is gone. **Recommended:** confirm on npmjs.com that the token is revoked (not merely expired), and rewrite history only if the orgs' policy requires it. `.npmrc` is now untracked entirely (`6b9f549`) so this class can't recur via this file.

### High

**H1 — url/param changes reloaded the iframe (flagship doc claim false).**
Evidence: `buildIframeSrc(url, extractParams(props))` ran on every render and fed the iframe `src` attribute (`SCWidget.tsx:377` pre-fix). React rewrites `src` on change, which navigates the iframe — while a separate effect (`SCWidget.tsx:284-307` pre-fix) *also* called `widget.load()`. Every `url` or player-param change loaded the player twice and dropped the widget's postMessage session. README, llms.txt ("URL/param changes trigger widget.load() — no iframe remount, no flicker"), and CHANGELOG 1.0.1 all documented the load()-only behavior.
**Fixed** (`3e1f4c6`): the src is frozen at mount (`useState` initializer); changes go through `widget.load()` exclusively. Changes landing before the API script is ready are caught up at widget init via a latest-props ref. Dead `prevUrl`/`prevParams` refs (written, never read) removed. Tests pin: src attribute unchanged across url+param rerenders; pre-script-ready url change applied at init.

**H2 — React 17 support claimed everywhere, but the component crashed on React 17.**
Evidence: `peerDependencies` `react >=17`, README comparison table "React version support ✅ >= 17", llms files — but `SCWidget.tsx:4` imported `useId`, which exists only in React 18+. On 17: `useId is not a function` at first render (or a module-evaluation failure depending on bundler interop).
**Fixed** (`aded4d1`): new `useStableId` resolves `React.useId` off the namespace import (so module evaluation succeeds on 17) and falls back to a counter-based per-instance hook. Documented caveat: the fallback is not SSR-stable — React 17 SSR users should pass `iframeId`. The fallback is unit-tested directly; full React 17 matrix CI was not added (see Remaining).

**H3 — Every callback-style getter invoked its callback twice.**
Evidence: `widgetRef.current?.getVolume(cb) ?? cb(0)` (`SCWidget.tsx:319-325` pre-fix). The widget methods return `void`, so the `??` fallback fired unconditionally: consumers got an immediate spurious default (`0`/`[]`/`true`) followed by the real value. Affected `getVolume`, `getDuration`, `getPosition`, `getSounds`, `getCurrentSoundIndex`, `isPaused`.
**Fixed** (`0a50eeb`): explicit if/else — exactly one invocation per call. Regression tests pin both the widget path and the pre-init default path. (The `*Async` variants were already correct.)

**H4 — Volume range documented as 0–1; the Widget API uses 0–100.**
Evidence: README Ref-methods table "Set volume (0–1)", "Get current volume (0–1)", hook example `controls.setVolume(0.5)` labeled "50% volume" (would be near-silent); llms.txt `setVolume(0-1)`. SoundCloud's official docs state "sets the widget volume to a value in the range 0-100" / "returns the current volume, in the range of [0, 100]". The repo's own demo (`demo/app/components/CustomControlsPlayer.tsx:74-82`) already used a 0–100 slider, contradicting the library's docs. Live behavior **ASSUMED**, but SC's official docs + the demo agree.
**Fixed** (`f9b4e7d`): 0–100 across README, both llms files, examples (`setVolume(50)`), and new JSDoc on `SCWidgetInstance`/`SCWidgetRef`.

### Medium

**M1 — Stale version headers in llms.txt / llms-full.txt (`2.0.0` at v2.0.4).**
The exact drift vector from the sibling incident: an agent reading the header would anchor on 2.0.0-era behavior, and the files predated the 2.0.1 snake_case fix they describe around. **Fixed** (`f9b4e7d`): headers now read 2.1.0 and the embedded behavior notes were re-synced against `src/` (frozen src, exactly-once getters, timeout retry, `onSeek`, `RefObject<SCWidgetRef>`).

**M2 — CHANGELOG missing the last four releases.**
v2.0.1–v2.0.4 shipped (npm dist-tag latest = 2.0.4) with no entries; the file stopped at 2.0.0. Notably 2.0.1 fixed params being **silently ignored** on `widget.load()` — the same "silent no-op" class as the sibling's C1 — and 2.0.2→2.0.4 were an init-timing back-and-forth worth recording. **Fixed** (`f9b4e7d`): entries backfilled from the tagged code/commits, plus the 2.1.0 entry.

**M3 — Script-loader poll timeout was permanent.**
Evidence: `useScript.ts:30-33` pre-fix — the 10s timeout path rejected but did not reset the module-level `scriptPromise` (the `onerror` path did), so after one timeout every future widget mount on the page failed forever; the timeout also stayed armed after success. **Fixed** (`2797298`): singleton reset on timeout, timer cleared on success. Regression test uses fake timers and proves a remount succeeds afterwards.

**M4 — No `"use client"` in the published files despite App Router positioning.**
Evidence: `dist/index.mjs`/`dist/index.js` had no directive; README/llms position the package for Next.js. Direct import into a Server Component tree fails on hooks. **Fixed** (`89bb500` + `88f0886`): tsup banner ships the directive in both formats. Note: tsup's `treeshake: true` (a rollup re-bundle) silently **dropped** the banner on the first attempt — verified in dist output, then removed the treeshake pass (consumer tree-shaking is covered by the new `sideEffects: false`). Verify-the-dist, not the config.

**M5 — Zero tests, no test CI, and a false "tested" claim.**
Evidence: no test files, no test script, no CI workflow other than publish; README and llms.txt claimed "**tested** duplicate-script injection prevention". The publish workflow also used `pnpm/action-setup` `version: latest` — the exact footgun that broke the siblings' CI (pnpm 11 rejects v9 lockfiles under `--frozen-lockfile`) — and published without running any tests.
**Fixed:** `95dd066` adds a 34-test vitest/jsdom suite (script-loader idempotency: two widgets → one script tag; pre-existing `window.SC` → no injection; load-failure surfacing + retry; all-11-event bind/unbind symmetry incl. StrictMode and remount; stale-closure safety; snake_case `load()` translation; SSR `renderToString` in bare Node; hidden mode; imperative ref + Promise getters; `useSCWidget` state transitions) and `ci.yml` (typecheck/build/test, Node 22+24, push+PR). `6b9f549` pins pnpm via `packageManager`; publish.yml now runs tests before publishing. The "tested" claim is now true.

**M6 — `useSCWidget().ref` did not typecheck against `<SCWidget ref>`.**
Evidence: typed `RefObject<SCWidgetRef | null>` (`useSCWidget.ts:6` pre-fix), which `@types/react` 18 rejects for the `ref` prop — the repo's own demo had to cast (`CustomControlsPlayer.tsx:28` `ref={ref as RefObject<SCWidgetRef>}`). **Fixed** (`95dd066`): `useRef<SCWidgetRef>(null)` yields the assignable `RefObject<SCWidgetRef>`.

**M7 — `.npmrc` and `dist/` tracked in git while listed in `.gitignore`.**
`.gitignore` listed both, but both were committed (gitignore doesn't untrack). The tracked `.npmrc` `${NPM_TOKEN}` placeholder also made every local `pnpm install` warn (`Failed to replace env in config`) and would hard-fail npm commands locally. **Fixed** (`6b9f549`): both untracked; OIDC publishing needs neither (v1.0.6–v2.0.0 published without `.npmrc` present).

### Low

**L1 — README "Demo" section duplicated 12 times** (clearly a generation accident). **Fixed** (`f9b4e7d`): once.
**L2 — LICENSE file missing.** `package.json` says MIT and the README badge linked `blob/main/LICENSE` → 404. **Fixed** (`f9b4e7d`): MIT LICENSE added.
**L3 — "Full type coverage matching the official Widget API spec" overclaim.** `showTeaser`, `visual`, `liking`, `showComments`, `hideRelated` are *not* in SC's official parameter docs (which end at `single_active`); they are de-facto params used by SoundCloud's embed builder (**ASSUMED** they keep working). **Fixed** (`f9b4e7d`): footnoted in README and llms files rather than removed — they're real, just not spec.
**L4 — `useSCWidget` ignored SEEK**, so `state.positionMs` went stale when the user seeked while paused. **Fixed** (`89bb500`): hook binds `onSeek`; docs updated (and the hook's named-prop occupancy + `onEvent` composition is now documented).
**L5 — Cross-package URL-format mismatch undocumented.** `soundcloud-api-ts@1.14.0`'s `getSoundCloudWidgetUrl()` returns a **pre-encoded** widget URL fragment (`https%3A//api.soundcloud.com/tracks/{id}&show_teaser=false&…`), while `<SCWidget url>` expects a plain unencoded URL and encodes it itself (`URLSearchParams.set`) — passing the helper's output would double-encode and embed bogus params. The two packages do **not** compose on that path. No doc here claimed they did, but the Related section now warns explicitly (`f9b4e7d`). The README's other cross-references (`getTrack(id, config, { revalidate })`, `useTrack` → `{ data }`) were verified accurate against the sibling sources.
**L6 — pnpm 10 blocked esbuild's install script** on every install (same as sibling L8). **Fixed** (`6b9f549`): `pnpm.onlyBuiltDependencies: ["esbuild"]`.

### Verified correct (no action)

- **Event/method surface matches SoundCloud's documented Widget API exactly** — all 11 events (`ready`, `play`, `pause`, `finish`, `seek`, `play_progress`, `load_progress`, `click_buy`, `click_download`, `open_share_panel`, `error`) and all methods (`bind`/`unbind`/`load`/`play`/`pause`/`toggle`/`seekTo`/`setVolume`/`next`/`prev`/`skip` + 7 getters) exist in both directions; nothing invented, nothing missing. `SCAudioEventPayload` (`relativePosition` 0–1, `loadProgress` 0–1, `currentPosition` ms) matches the official payload description verbatim. UI events typed `undefined` payload — SC's docs specify none (**ASSUMED**).
- **SSR safety**: no `window`/`document` access during render; `useScript` guards `typeof window` and only runs in effects. Pinned by a bare-Node `renderToString` test.
- **Script loader idempotency** (1.0.7 claim): singleton promise + DOM-tag poll + pre-existing `window.SC` detection all behave as documented; now pinned by tests.
- **Stable callback refs** (1.0.1 claim): handlers update without re-binding; no stale closures. Pinned by test.
- **StrictMode / remount symmetry**: init guard + full unbind cleanup verified; the 2.0.3/2.0.4 remount regression area is covered by an explicit remount test.
- **snake_case `load()` translation** (2.0.1 fix) and **single-encoding iframe src** (1.0.8 fix): intact, pinned by tests.
- **Prop defaults match docs**: `width "100%"`, `height 166`, `allow "autoplay"`, hidden-mode 1×1 style. Pinned.
- **Publish pipeline**: GitHub Release → OIDC trusted publishing, history green; npm `latest` = 2.0.4 matched the repo at audit start.
- **`SC.Widget()`-immediately init strategy** (2.0.4): structurally sound — params are baked into the iframe src, and SC handles readiness via postMessage READY (**ASSUMED** for live behavior; the code-level invariants are tested).

## Remaining (not fixed, with reasons)

1. **Leaked token still in git history and in tags v2.0.1–v2.0.3** (C1). Verified revoked (401). Scrubbing means force-pushing rewritten history and re-tagging — destructive and signature-breaking; needs an explicit maintainer decision. The file itself is untracked now.
2. **React 17 is not exercised in CI.** The shim's fallback path is unit-tested directly, but devDependencies are React 18 and RTL 16 requires 18+. A true 17 job needs a separate install matrix — worth doing if 17 support matters beyond the claim; the cheaper alternative is bumping peers to `>=18` in the next **major** and deleting the shim.
3. **`useSCWidget` props/controls object identities change per render** (the inner callbacks are stable, the wrapping objects aren't). Harmless with `<SCWidget>` (callback refs absorb it), but `controls` in a consumer dep array re-fires effects. Memoizing is a small follow-up; left out to keep the audit pass minimal.
4. **`hidden` mode iframe keeps `width`/`height` HTML attributes off but inline-styles 1×1** — fine, but toggling `hidden` at runtime relies on React patching the same iframe element; an explicit test for the toggle path wasn't added.
5. **Demo app is not built in CI** (own workspace/lockfile). Its volume slider was already correct; no changes made there.
6. **CHANGELOG 1.0.x entries** verified for internal consistency only, not against each old tag (low value vs cost) — **ASSUMED** historical record.
7. **Live-widget behavior** (postMessage timing, `load()` queueing before READY, de-facto params, volume range at runtime) — **ASSUMED** throughout; verify in a browser smoke test if SC changes the player.
